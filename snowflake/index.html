Live Lab Session

AI agents can reason, but on their own they cannot safely reach your governed enterprise data, and wiring each one up by hand is brittle and hard to govern. Snowflake's managed MCP server solves the connection, but the more interesting question is what you let an agent actually do once it is connected.

The managed MCP server turns the Model Context Protocol into a native Snowflake object. We assemble exactly the tools we want with a single CREATE MCP SERVER statement, so the tool surface — and the blast radius — is a deliberate design choice. Every call runs as the connecting user's role, with OAuth, RBAC, masking, and audit applied automatically.

Cortex Analyst Cortex Search SYSTEM_EXECUTE_SQL GENERIC CORTEX_AGENT_RUN

In this hands-on lab, we move from answers to actions

For Snowflake customers and Solutions Engineers who want to move past read-only question answering.

1

Build the read tools first

A semantic view for Cortex Analyst and a Cortex Search service, then assemble a scoped MCP server and connect a live AI client.

2

Let the agent run its own queries

Add SYSTEM_EXECUTE_SQL, and see how read_only and your role cap what it can touch.

3

Take a real, audited action

Wrap a stored procedure as a GENERIC tool and watch the agent read customer reviews and then file a support ticket — all on a scoped warehouse with least privilege.

4

Optionally, delegate multi-step work

Expose an entire Cortex Agent as a single tool, or serve Cortex Code over MCP.
